Shipping a Manifest V3 extension without losing your mind

Sam Rivera · 8 min read · Updated today

Migrating from Manifest V2 changed how background code runs: the persistent background page is gone, and a service worker takes its place. That single change ripples through storage access, message passing, and every assumption you had about long-lived state.

Why the service worker keeps sleeping

A service worker is evicted after a short idle period, so anything cached in a module-level variable can vanish between two user actions. The fix is not to fight the lifecycle — it is to treat chrome.storage as the source of truth and rehydrate on every wake-up. 

chrome.storage.sync.get(null, (items) => {
  state = items || {};
  console.log("rehydrated", Object.keys(state).length, "entries");
});

Injecting code at the right moment

Content scripts declared at document_start run before the page paints, which is what you want for style overrides. Anything that touches the DOM tree needs to wait, either for document_end or for an explicit observer.

Permission budget

Reviewers read your permission list closely. Keep it to what you can justify in one sentence each.

PermissionUsed forOptional
storageSaving user rulesNo
scriptingRunning the user's own codeNo
tabsReading the active tab URLNo
offscreenKeeping a local socket aliveYes

What to test before you submit

Load the unpacked build, open three surfaces at once — popup, side panel, options — and change a value in one. If the other two do not update, your storage listener is wired incorrectly.
